# snap-meal v0.1.4

发布日期：2026-08-02

本版本打通订单履约链路的"最后一公里"。后端履约能力（接单、拒单、取消、派送、完成）在此前的版本中已经就绪，本次迭代将其完整接通到管理端和 Web 用户端界面，并补齐履约链路的自动化测试。

## 更新重点

### 管理端订单管理增强

- 订单页新增状态筛选：
  - 全部、待付款、待接单、已接单、派送中、已完成、已取消
  - 每个筛选按钮实时显示对应状态的订单数量角标
  - 数据来自 `/api/admin/orders/statistics`

- 订单页新增订单号搜索：
  - 支持按订单号模糊搜索
  - 输入与触发分离，避免逐字符发起请求

- 订单操作补全：
  - 待接单订单支持接单和拒单
  - 拒单和取消需要填写原因，原因写入订单并持久化
  - 待接单、已接单订单支持取消
  - 已接单订单支持派送，派送中订单支持完成

- 订单页新增详情展开：
  - 收货人、联系电话、完整地址
  - 订单备注
  - 下单时间、预计送达时间、实际送达时间
  - 拒单原因、取消原因
  - 菜品明细表（菜品名、数量、单价）

### Web 用户端订单追踪

- 新增"我的订单"视图：
  - 页面头部可在"点餐"和"我的订单"之间切换
  - 订单卡片展示状态、订单号、金额、下单时间
  - 履约中的订单展示预计送达时间
  - 被拒单或取消的订单展示对应原因

- 用户可取消待付款、待接单状态的订单。

- 支付成功后自动跳转到"我的订单"，用户可立即看到订单进入"待接单"状态。

- 管理端与用户端的订单状态文案统一为同一口径：
  - 待付款、待接单、已接单、派送中、已完成、已取消

### 履约链路测试

- 抽取下单流程公共方法，新增三个集成测试用例：
  - 完整履约生命周期：支付后接单、派送、完成，逐步断言订单状态和送达时间
  - 拒单携带原因：断言订单状态变为已取消且拒单原因正确持久化
  - 非法状态迁移：未接单直接派送或直接完成返回 400

- 后端测试用例总数从 6 个增加到 9 个。
